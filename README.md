# AI電話一次応答 — 会話検証キット

要件書 `ai-phone-agent-spec.md` の**会話部分だけ**を、050番号もキャリア転送も使わずに検証するための実験環境です。

## これで何が分かるか

要件書 §10「検証すべき前提」のうち、**AIがどこまで会話を成立させられるか**が分かります。

| 指標(§1.3) | 目標 | どこで見るか |
|---|---|---|
| 要件の聞き取り成功率 | 80%以上 | `replay.mjs` の合格率 |
| 体験予約の完了率 | 50%以上 | `logs/calls.jsonl` の `booked` |
| 応答の遅延 | 1.5秒以内 | 画面の「応答の遅延」表 |

**着信数と応答率(§11 第1段階)はここでは分かりません。** それには050番号を発行してホームページの掲載番号を差し替える必要があり、教室の協力が要ります。この2つは独立しているので並行して進められます。

## 構成

```
携帯(スピーカーフォン) → PCのマイク → Google STT → Claude → Google TTS → PCのスピーカー → 携帯
```

- 会話の進行はステートマシン(`lib/dialog.mjs`)が持ちます。LLMには渡しません(§7.4)
- LLMの担当は「要件分類とスロット抽出」「定型で返せない場合の応答文」の2つだけです
- 定型文は起動時に音声を作り置きします(§7.1)

## 準備

### 1. GCP

```bash
gcloud config set project <プロジェクトID>
gcloud services enable speech.googleapis.com texttospeech.googleapis.com
gcloud auth application-default login
```

認証が無いと起動時に止まります。音声認識と音声合成の両方が必須です。

### 2. 環境変数

`.env.local` に以下を足します。`ANTHROPIC_API_KEY` は既存のものを使います。

```bash
# 通知の宛先(§5.1)。いずれも「教室の先生」の連絡先。保護者には送らない
# 未設定ならコンソールに出るだけ
CLASSROOM_NOTIFY_EMAIL=
CLASSROOM_NOTIFY_SMS=

# SMSの送信元。Twilio は日本の送信用番号を出していないため、
# 米国番号か、事前登録した英数字の送信者IDになる
TWILIO_ACCOUNT_SID=
TWILIO_AUTH_TOKEN=
TWILIO_SMS_FROM=

# 仮予約を入れる Google カレンダー(未設定ならスキップ)
# サービスアカウントを使う場合、そのアドレスにカレンダーを共有しておくこと
CALENDAR_ID=

# 教室データをスプレッドシートから読む場合(未設定なら data/classroom.sample.json)
CLASSROOM_SHEET_ID=

# 声を変えたいとき
TTS_VOICE=ja-JP-Chirp3-HD-Aoede
TTS_SPEAKING_RATE=0.92

# 話し終わりの判定(短くすると速いが、話の途中で応答してしまう)
STT_SETTLE_MS=900          # 認識が確定してから続きを待つ時間
STT_CONTINUATION_MS=800    # 「〜ですけど」など、まだ続きそうな語尾のときの追加待ち
STT_SPEECH_END_MS=1200     # Google 側が話し終わったと判断するまでの無音の長さ
```

### 3. 教室データ

**サーバ起動後に `http://localhost:8788/admin.html` を開くと、ブラウザから設定できます。**

- 応答モード(おまかせ / 受付のみ)と見学の受け付け
- 在籍生徒の登録・削除(登録番号からの着信は伝言モードで受ける)
- AIが答えてよい案内事項の追加・削除
- コースごとの月謝と、枠ごとの空き状況(空き状況を変えると更新日が今日になる)

保存すると次の着信から反映されます(サーバの再起動は不要)。実体は `data/classroom.json` で、
直接編集しても構いません。`CLASSROOM_SHEET_ID` でスプレッドシート運用にしている場合、
管理画面は読み取り専用になります。
`slots[].updatedAt` は §4.3 の鮮度判定に使うので、実際の更新日を入れてください。

教室ごとの振る舞いは同じファイルで設定します。

```jsonc
{
  "settings": {
    "mode": "full",        // full=仮予約まで進める / reception=用件と連絡先だけ預かる
    "allowTour": true      // 教室見学(見るだけ)を受け付けるか
  },
  // 先生が承認した案内事項。§3.4 の定型範囲を超えていても、ここに書いた内容は
  // AIが「先生の代読」として答えてよい。書いていないことは先生へ渡す
  "notes": [
    "体験レッスンは無料",
    "個別(マンツーマン)での体験レッスンは、先生と日程を調整のうえ対応できる"
  ],
  // 在籍生徒。登録番号からの着信は伝言モードで受ける(予約フローに引き込まない)
  "students": [{ "name": "山本", "phone": "09055551111", "grade": "小3" }]
}
```

### 受け付けられる言い直し

会話の途中の訂正は、どの段階でも受け付けます。

| 言い直し | 例 |
|---|---|
| 学年 | 「2年生」→「中学2年生です」(小2と解釈した後でも学年からやり直す) |
| 体験⇄見学 | 「体験じゃなくて見学だけしたい」 |
| コース | 枠選び中の「やっぱり英検のほうで」 |
| 枠 | 確認中の「やっぱり金曜日で」 |
| 氏名 | 連絡先確認中の「田中ではなく中田です」 |
| 日時が合わない | 時間割に無い希望・満席は断らず「要相談」の仮予約として預かる |

## 使い方

### 会話ロジックの採点(マイク不要)

```bash
npm run phone-agent:replay
```

`data/scenarios.json` の台本を流して、要件書の各条項が守られているか採点します。
会話設計を直したら、まずこれを通してから実機に移ってください。1件だけ流すこともできます。

```bash
npm run phone-agent:replay -- trial-basic
```

### 実機での通話

```bash
npm run phone-agent
```

`http://localhost:8788` を開き、携帯をスピーカーフォンにしてマイクの前に置きます。
「通話を開始」を押してから、保護者役として話しかけてください。

- 発信者番号を入れておくと、番号を聞き取れなかったときの折り返し(§7.3)を確認できます
- 通話の録音は `logs/recordings/` に、文字起こしと結果は `logs/calls.jsonl` に残ります

### 実際の電話で受ける(Twilio)

`lib/twilio-stream.mjs` が Twilio Media Streams を受けます。会話・教室データ・通知は
ブラウザ版と完全に同じものを使うので、番号を差し替えても作り直しは発生しません。

音声は 8kHz μ-law のまま扱います。Google の認識・合成が両方この形式に対応しているため
変換が不要で、§7.2「電話回線の帯域(8kHz)に最適化する」も満たせます。

**番号を買う前に、電話の経路だけ確認できます。**

```bash
npm run phone-agent          # 別のターミナルで起動しておく
npm run phone-agent:sim      # Twilio のふりをして通話を1本流す
```

実際の電話につなぐ手順:

```bash
# 1. サーバを起動
npm run phone-agent

# 2. 別のターミナルで公開URLを作る(表示された https://....trycloudflare.com を控える)
npm run phone-agent:tunnel
```

3. Twilio コンソールで購入した番号を開き、**A CALL COMES IN** に
   `https://<控えたホスト>/twilio/voice`(HTTP POST)を設定して保存

トンネルを張り直すとURLが変わるので、そのつど Twilio 側の設定も更新してください。

#### 無料トライアルの制限

- 着信すると英語の案内が流れ、発信者がキーを押す必要があります
- **着信元は Twilio で認証済みの番号に限られます**
- 同時通話は5本まで

自分の番号を認証すれば動作確認はできます。他の人に触ってもらうならアカウントの有料化が必要です。

## 台本を足す

`data/scenarios.json` に追記します。`expect` に書けるもの:

| キー | 意味 |
|---|---|
| `intent` | 要件の分類 |
| `grade` | 学年(小1=1、中1=7) |
| `booked` | 仮予約に到達したか |
| `slotIncludes` | 予約された枠に含まれるべき文字列 |
| `phone` | 最終的な連絡先 |
| `handedOff` | 連絡先の聴取に移ったか |
| `firstReplyIncludes` | 1手目の応答に含まれるべき文字列 |
| `neverSays` | 通話中に一度も言ってはいけない文字列 |
| `ends` | 台本を流し終えて通話が終わっているか |

`neverSays` と `firstReplyIncludes` は「正しい理由で合格しているか」を担保するために使います。
最終結果だけを見ていると、途中で仕様違反をしていても通ってしまいます。

**この採点は実行ごとに少しぶれます。** 要件の分類をLLMが行っている以上、同じ台本でも
判定が変わることがあります(実測で10件中1件程度)。1回の結果で判断せず、
数回まわして安定して80%を超えているかを見てください。

## 分かっている制約

- **電話回線が無い。** Google には日本で使える電話番号の払い出しAPIがありません。実際に050へ着信させる段階では、番号は Twilio 等の外部事業者になり、ブラウザとの音声のやり取りを Twilio Media Streams に差し替えます(会話ロジック以下はそのまま使えます)。
- **Chirp3 HD は発話速度を変えられない。** §7.2 の「やや遅い発話速度」は、この声では指定しても無視されます(起動時に警告が出ます)。速度を効かせたい場合は `TTS_VOICE=ja-JP-Neural2-B` に切り替えてください。
- **氏名と電話番号の復唱は事前合成できない。** 実測で合成に1.5〜2.2秒かかり、ここだけ §1.3 の1.5秒を超えます。それ以外の文は起動時に作り置きするので0msです。
- **音質が実回線と違う。** ここは16kHzのマイク入力ですが、実際の電話は8kHzです。聞き取り精度は実回線のほうが落ちます。
- **話し始めの割り込みに未対応。** AIが喋っている最中の発話は捨てます。実回線では割り込みへの対応が要ります。
- **メール送信は Resend。** Gmail API での送信はユーザー同意のOAuthが要るため、プロジェクト既存の Resend に合わせています(`src/lib/mail.ts` と同じ挙動で、キー未設定ならコンソール出力)。
